# Internationalisation (i18n)

This document fixes the localisation policy for the AriadShift user interfaces: the web app (`apps/web`) and the macOS app (`apps/macos`). It records the library, the catalogue format and path, the generation of macOS String Catalogs, the translation management system, the machine-translation bootstrap rule, per-locale review status, right-to-left (RTL) support, the pseudo-locale and the string-freeze rule, and it lists every locale of the first preview.

It implements the i18n decision in the [Decision Log](../ARCHITECTURE.md): one source catalogue, generated per-surface catalogues, 40+ locales at first preview, `en` and `vi` human-reviewed, all others machine-bootstrapped and marked "community".

Approved by the Mac PM on the owner's delegation, 2026-11-01: next-intl 4.14.9, locales/en.json, the 42-locale list with en and vi reviewed, completeness thresholds 100% reviewed and 80% community, CLI/MCP/API/engine text English, 7-day string freeze.

## Scope

| In scope | Out of scope |
|---|---|
| Visible text of the web app and the macOS app | CLI output, MCP tool descriptions, HTTP API error text and the `ariad-engine` protocol. These stay English so scripts, agents and logs remain stable. |
| Number, date and list formatting through the platform's locale APIs | Repository documentation (`docs/`), which is English only |
| Plural and gender selection through ICU MessageFormat | Text inside converted documents. A conversion never translates content. |

Error codes and diagnostic identifiers are never translated. A surface maps a stable code to a catalogue key and shows the translated text next to the code.

## Decisions

| Topic | Decision |
|---|---|
| Web library | `next-intl` 4.14.9 (MIT). Locale lives in the URL path and every locale is prerendered, which works with the static export that `apps/web` already supports (`ARIADSHIFT_WEB_OUTPUT=export`). |
| Web fallback | Paraglide JS (MIT) only if the proof of concept below shows that next-intl message bundles are too large. |
| Catalogue format | ICU MessageFormat in nested JSON, one file per locale. |
| Source catalogue | `locales/en.json`, English, in git. It is the only file a developer edits by hand. |
| macOS catalogue | `Localizable.xcstrings` generated from `locales/*.json`. Never edited by hand. |
| Translation management | Hosted Weblate (owner decision). Weblate is a service the project uses, not code it ships or links. |
| Machine translation | Bootstrap only, as drafts that need review. See [Machine-translation bootstrap](#machine-translation-bootstrap). |
| Reviewed locales | `en`, `vi`. |
| RTL | `ar` and `fa`. |
| Pseudo-locales | `en-XA` and `ar-XB`, generated at test time and never shipped. |
| Freeze | Seven days before each preview tag. See [String freeze](#string-freeze). |
| Completeness thresholds | 100% for `reviewed` locales, 80% for `community` locales. See [Review status and completeness gate](#review-status-and-completeness-gate). |
| Text outside the UI | CLI output, MCP tool descriptions, API error text and the `ariad-engine` protocol stay English. |

### Why next-intl

The UI-surface research (`plans/reports/researcher-261031-2115-ui-surface-tech.md`, section A1) ranks next-intl first among next-intl, Paraglide JS, Lingui and i18next for a Next.js App Router site with static export, 40+ locales, RTL and ICU plurals. It has strong app-wide message types, ICU MessageFormat support and a documented static-export path. Its peer range already covers the repository's Next.js 16. The registry confirms 4.14.9 as the current release (checked 2026-11-01); pin the exact version through the lockfile when the web phase adds it, and re-check the registry then.

Two limits apply to the static export, both from the same report:

- Proxy-based locale detection does not run, so the locale always comes from the path (`/vi/...`). A small client-side redirect from `/` may suggest a locale from `navigator.languages`, but it must never be the only way to reach a locale.
- Every locale page needs `generateStaticParams`.

**Proof-of-concept gate.** The per-locale bundle size is unmeasured. Before the web phase commits to next-intl, build a page with the full `vi` catalogue and a page with the full `en` catalogue, and record the transferred JavaScript and message payload for each. If one locale's messages add more than 5% to the first-load payload of the converter page, evaluate Paraglide JS (compile-time, per-message imports) as the replacement. The catalogue format and pipeline in this document do not change in that case, because both libraries read ICU MessageFormat.

## Source catalogue

### Path and layout

```text
locales/
  en.json            source catalogue (English, hand-edited)
  <tag>.json         one translation file per locale, written by Weblate
  locales.toml       locale metadata: direction, review status, RTL check
```

`<tag>` is a BCP 47 tag in canonical casing (`pt-BR`, `sr-Latn`, `zh-Hans`). Files hold nested JSON objects. The metadata file is TOML and uses a different name pattern on purpose, so the Weblate file mask `locales/*.json` never picks it up.

### Namespaces

The first key segment decides which surface receives a string.

| Namespace | Delivered to | Notes |
|---|---|---|
| `common.*` | web and macOS | Shared product vocabulary: tool names, formats, statuses, errors. Uses the portable ICU subset only. |
| `web.*` | web only | May use rich-text tags, for example `<b>…</b>` and `<link>…</link>`. |
| `mac.*` | macOS only | Menu items, window titles, system-integration text. Portable ICU subset only. |
| `legal.*` | web and macOS | Licence, privacy and notice text. Never machine-translated; see below. |

### Portable ICU subset

Strings in `common.*`, `mac.*` and `legal.*` must convert to a String Catalog without loss, so they may use only:

- simple arguments, `{name}`
- `plural` with CLDR categories, `{count, plural, one {# file} other {# files}}`
- `select`, `{kind, select, pdf {…} other {…}}`
- at most one level of nesting

Number, date and relative-time styles inside messages are not allowed. Format values in code with the platform formatter and pass the formatted text as an argument. Rich-text tags and `selectordinal` are allowed in `web.*` only. A CI check rejects anything else in the shared namespaces.

### Key rules

- Keys are lowercase, dot-separated by nesting, and name the meaning, not the English wording: `common.tool.merge.title`, not `common.merge_pdf_files`.
- A key's English text may change without changing the key only when the meaning stays the same. If the meaning changes, use a new key so old translations do not silently become wrong.
- Every key that is not self-explanatory carries a translator note in a sibling key ending in `@note`. Weblate shows it as context.
- Product names (`AriadShift`, `ashift`), format names (`PDF`, `DOCX`, `EPUB`, `Markdown`, `HTML`) and engine names stay in a shared glossary and are marked untranslatable.
- No string is built by concatenation. Order of words differs between languages, so every sentence is one message with arguments.

## macOS String Catalogs

Apple's String Catalog (`.xcstrings`) is the macOS format. AriadShift does not translate it directly. A generator reads `locales/*.json` and writes `apps/macos/…/Localizable.xcstrings`, so there is one source of truth and one translation workflow.

| Step | Rule |
|---|---|
| Select | Keep `common.*`, `mac.*` and `legal.*`. Drop `web.*`. |
| Keys | Use the dotted JSON path as the catalogue key, unchanged. |
| Arguments | `{name}` becomes a positional format specifier (`%1$@`, or `%1$lld` for numeric arguments, decided by the argument type declared in the source note). |
| Plurals | `plural` becomes a `variations.plural` entry, one variation per CLDR category the locale uses. `#` becomes the numeric specifier. |
| Select | String Catalogs have no `select` construct, so the generator emits one catalogue key per branch (`<key>.<branch>`) and the Swift call site picks the branch. |
| State | Weblate `approved` and `translated` map to `translated`; `needs editing` maps to `needs_review`; untranslated strings are omitted so the system falls back to the source language. |
| Source language | `en`. The catalogue's `sourceLanguage` is `en`. |
| Output | Deterministic key order and fixed indentation, so a second run produces no diff. |

The generated catalogue is committed, because Xcode builds from the repository. CI regenerates it and fails when the committed file differs. The generator and its tests are written in the macOS phase; this document fixes only the contract.

Xcode may add or reorder entries when it opens the catalogue. Developers must not accept those edits: change `locales/en.json` and regenerate.

Swift code reads strings through a single typed wrapper generated from the same key list, so a missing key is a compile error rather than a runtime fallback. This follows the "Swift carries no document logic" rule in [ARCHITECTURE.md](../ARCHITECTURE.md).

## Translation management: hosted Weblate

The owner chose hosted Weblate. The UI-surface research ranked Weblate first on its Git-native workflow; with the hosted service the GPL-3.0 server is not run, shipped or linked by this project, which removes the licence question raised in that report for self-hosting.

| Setting | Value |
|---|---|
| Service | The hosted Weblate service operated by the Weblate project. The project uses the free Libre plan for public projects if the repository qualifies at setup time; otherwise a paid hosted plan (open question 1). |
| Component | One component for `locales/*.json`. |
| File format | JSON nested structure file (`json-nested`), monolingual. |
| File mask | `locales/*.json` |
| Monolingual base file | `locales/en.json` |
| Translation flags | `icu-message-format`, so Weblate's ICU MessageFormat and ICU syntax checks run on every string. |
| Glossary | One shared glossary for web and macOS, with untranslatable product, format and engine names. |
| Repository access | A GitHub App or deploy credential created by the owner in Weblate's and GitHub's settings. Never committed; held as a secret. |
| Push method | Weblate opens a pull request against `dev`. It never pushes to `dev` or `main` directly. |
| Commit message | Template `chore(i18n): update {{ language_name }} translation`, no body template, no trailers, so the commit lint (`committed.toml`, `scripts/check-commits.sh`) passes. |
| Source changes | Developers change `locales/en.json` in git. Weblate pulls from `dev` through a webhook and never edits the source strings. |
| New languages | Added by a pull request that adds the locale to `locales/locales.toml` and creates its empty file. Weblate's "start new translation" is disabled so the list stays controlled. |

Until the hosted Weblate project exists, phase 14 works with git-only catalogues: `locales/*.json` is edited in git and the same checks run.

Configuring the hosted project, the GitHub App and the webhook needs the owner's accounts and is an owner action. The repository only records the settings above.

The macOS app needs no separate Weblate component, because its catalogue is generated. The research question whether Weblate imports `.xcstrings` directly therefore does not affect the design.

## Machine-translation bootstrap

A new locale starts from a machine draft so the first preview can offer 40+ languages. The rules keep drafts from posing as reviewed text.

1. **Drafts only.** Machine output is committed in the "needs editing" state, never "approved". Weblate's automatic translation or an LLM may produce it; the engine is not part of this contract (open question 2). Whatever produces drafts must permit commercial use of its output and must not retain the submitted strings for its own training.
2. **Never overwrite people.** A draft is written only into an untranslated string. A string a human translated or approved is never replaced by a machine draft.
3. **Placeholders must survive.** A draft that fails the ICU checks (missing argument, broken plural, altered tag) is rejected and left untranslated.
4. **Glossary first.** Untranslatable names stay in English inside the draft.
5. **No machine text for legal copy.** `legal.*` is never machine-translated. Locales that are not human-reviewed show the English text for those keys.
6. **Label it.** Every locale that holds machine-drafted text is marked `community` in `locales/locales.toml`. The language picker shows a "Community translation" badge next to it, and the about screen links to the Weblate project so users can correct text.
7. **Promotion.** A locale changes from `community` to `reviewed` only when a native reviewer has approved 100% of `common.*`, `web.*` and `mac.*` strings in Weblate and `legal.*` has a human translation. The change is a pull request that edits `locales/locales.toml`.

### Review status and completeness gate

The status of each locale lives in `locales/locales.toml`, not in the translation file:

```toml
[locale.vi]
name = "Tiếng Việt"
dir = "ltr"
status = "reviewed"

[locale.ar]
name = "العربية"
dir = "rtl"
status = "community"
rtl_checked = false
```

A release build checks every locale against this gate:

| Locale status | Required to appear in the language picker |
|---|---|
| `source`, `reviewed` | 100% of keys translated and approved. A missing key fails the build. |
| `community` | At least 80% of keys translated. Missing keys show English. Below 80% the locale is hidden from the picker and its file stays in git. |
| `community` and `dir = "rtl"` | The 80% rule plus `rtl_checked = true`, which a native reader sets after reviewing the main screens in the real layout. |

The RTL condition follows the research advice not to auto-publish RTL copy: machine text in `ar` and `fa` is acceptable as community text only after a person has seen it rendered right to left.

## Right-to-left support

- The root layout sets `lang` and `dir` from the locale metadata, never from string checks.
- Web styles use Tailwind CSS logical utilities (`ms-`, `me-`, `ps-`, `pe-`, `start-`, `end-`, `text-start`). Physical `left`/`right` utilities are flagged by lint for layout in the shared UI package.
- Icons that show direction (back, forward, progress, undo) mirror in RTL. Icons that show an object (a document, a lock) do not.
- Document previews are never mirrored: a PDF page and a converted document keep their own direction.
- Numbers, dates and lists go through `Intl` (web) and the system formatters (macOS), so digit shapes and separators follow the locale.
- macOS uses SwiftUI's leading and trailing edges and the system layout direction, so no direction code is written by hand.
- Mixed-direction values such as file names, paths and commands are wrapped in an isolate (`<bdi>` on web, Unicode isolates on macOS) so they do not reorder the surrounding sentence.

## Pseudo-locales

Two generated locales exist for tests only. They are produced at test time from `locales/en.json`, written to a cache folder, never committed and never listed in `locales/locales.toml` or the picker.

| Tag | Transform | Catches |
|---|---|---|
| `en-XA` | Accents every Latin letter, pads each message by about 40%, wraps it in `[` and `]`, leaves arguments and tags intact | Hard-coded English (it shows as unaccented text), truncated or overflowing layouts, concatenated sentences |
| `ar-XB` | Wraps each message in right-to-left marks and reverses word order, leaves arguments and tags intact | Layout that breaks in RTL, physical left/right styling, unisolated mixed-direction text |

Required tests:

- A unit test renders the main screens at `en-XA` and fails if any visible text contains an unaccented English word outside arguments and glossary names.
- A Playwright test loads the converter at `en-XA` and `ar-XB`, checks `dir`, and fails on horizontal overflow or clipped controls at the supported viewport widths.
- A generator test checks that both transforms keep every ICU argument, plural branch and tag.

## String freeze

Before each preview tag the English catalogue freezes so translators work against fixed text.

| When | Rule |
|---|---|
| Seven days before the tag | The maintainer opens the freeze. From then on a pull request that changes `locales/en.json` must carry the label `i18n-freeze-exception` and a maintainer approval; CI fails otherwise. |
| During the freeze | Weblate has the final English text. `vi` is translated and approved in this window. |
| Three days before the tag | The completeness gate runs against `dev`. A failing `reviewed` locale blocks the tag. |
| The tag | The freeze ends when the tag is cut. |

New keys, changed English text and removed keys all count as changes. Fixing a typo in English during the freeze needs the exception label too, because it invalidates translations that were reviewed against the old text.

## CI checks

All checks run on `locales/` and are part of the web and macOS gates once those phases add them.

1. **Valid ICU.** Every message in every locale parses.
2. **Argument parity.** A translation uses exactly the arguments, plural categories and tags of its English source (plural categories follow the target language's CLDR set).
3. **No stray keys.** A translation file has no key that `locales/en.json` lacks.
4. **Portable subset.** `common.*`, `mac.*` and `legal.*` use only the portable ICU subset.
5. **Metadata.** Every `locales/*.json` file has an entry in `locales/locales.toml`, and every entry has a file.
6. **Generated output.** The committed `Localizable.xcstrings` equals a fresh generation.
7. **Freeze.** During a freeze, `locales/en.json` changes need the exception label.

## Open questions

1. **Hosted plan.** Does the repository qualify for the free Libre plan, which Weblate's hosting page limits to public projects, or does the project need a paid hosted plan? The owner confirms when creating the hosted project.
2. **Machine-translation engine.** Which engine produces the bootstrap drafts, and under which terms? The rules above fix how drafts are used, not who writes them.
3. **Bundle size.** The proof-of-concept gate has not run, so next-intl's per-locale payload is unmeasured.
4. **Reviewers for `en` and `vi`.** Who reviews each release is not named here. Two Vietnamese reviewers would remove a single point of failure.
5. **RTL reviewers.** No native `ar` or `fa` reader is arranged. Until one is, both locales stay hidden from the picker.
