# Phase 5: Heavy-route bench, freeze, v0.2.0

## Goal

Measure every new route, freeze the engine protocol and the IR, publish the first signed docling pack, and release `v0.2.0`. This closes roadmap 1b.

Read first: `docs/bench.md`, `bench/`, `fixtures/gen/`, `.github/workflows/{bench,release,release-smoke}.yml`, `docs/releasing.md`, phases 1–4 and their design notes.

## Requirements

### Bench and capabilities

- Fixtures with authored truth: digital PDFs (English and Vietnamese, with tables and multi-column pages) rendered from block lists; scanned PDFs and PNGs made by rasterizing those pages with mild noise and skew; PPTX, XLSX and DOCX generated with the existing Python generator. Every file recorded in `fixtures/manifest.toml`.
- Routes measured: `pdf → md` (Rust PDF reader, docling), scan `→ md` and `→ docx` (docling with Tesseract and with RapidOCR), `pptx|xlsx → md` (docling), Office `→ pdf` (LibreOffice), `md|docx → pdf` (Typst through IR and LibreOffice). Metrics as `docs/bench.md` defines, plus SSIM for the `faithful` profile (pypdfium2 raster in `bench/`).
- `crates/ariad-core/data/capabilities.json` regenerated by `bench/`; the planner picks docling for `editable` PDF routes and the Rust reader for `fast`.
- A public report `docs/bench-report.md`, generated from the capabilities file plus the methodology link, covering the PDF routes.

### Freeze

- `ariad-engine/1` loses its draft status; `ariad-ir/1` with `schemas/ir.v1.json`; readers accept `ariad-ir/0` documents. The conformance suite runs against the Pandoc, PDF, Typst, LibreOffice and docling engines; docling in a nightly or labelled job.

### Pack publication

- The coordinator generates the production minisign key pair, commits the public key under `crates/ariad-host/data/pack-keys/`, and stores the secret key as `PACK_MINISIGN_KEY` in the `release` environment.
- `pack-docling.yml` on a `pack-docling-v<version>` tag builds the four targets, writes one manifest, signs it in a job that alone sees the secret, and publishes a GitHub Release with the manifest, signature and components.
- `.github/workflows/pack-smoke.yml` installs `ashift` built from the tag's commit, runs `ashift engines install docling`, and converts a scanned PDF to DOCX on `macos-26`, `ubuntu-26.04` and `windows-2025` (Tesseract installed from each platform's package manager).

### Release v0.2.0

- Version bump to 0.2.0 on `dev`, README and docs for the new routes and packs, promotion of `dev` to `main` (merge commit), tag `v0.2.0` on `main`, `release.yml` watched to completion, `release-smoke.yml` for the channels that published. Record the evidence in a report under this plan.

## Acceptance criteria

- Roadmap 1b criteria in ARCHITECTURE §17 hold: protocol frozen after Docling conformance; public benchmark report for PDF routes; signed docling pack installs and verifies on three platforms; scanned PDF → DOCX succeeds locally.
- `v0.2.0` exists on GitHub Releases with the CLI archives and installers.

## Design notes: bench and freeze delivery

This branch owns the bench/capabilities and freeze sections only. Pack publication, production signing, release smoke against a published pack, the version bump and release remain coordinator work; the whole phase stays open until those outcomes hold.

- Reuse authored block lists for structured PDF and scan truth, including English and Vietnamese tables and columns. Record generated inputs and truth hashes in the fixture manifest.
- Measure engine edges explicitly so current planner choices cannot select the engine under test. Record end-to-end heavy routes separately, including both OCR backends and page SSIM from PDFium renders; never substitute route timings for individual edge timings.
- Emit IR v1 and accept v0 in both native and in-memory readers. Preserve the v0 schema for existing documents. Freeze the engine schema after running the real adapters through shared conformance checks.
- Keep unmeasured edges null and failed conversions visible. Generate the public report from capabilities and persisted route evidence.
- Measure DOC/RTF/ODT to DOCX normalization alongside Office PDF output. Otherwise measured PDF edges beat unmeasured structured normalization and regress editable Office routes.
- Profile selection is verified on the format graph. Retain the accepted content-aware native PDF selector: digital text uses the built-in reader, scans require Docling, and an explicit reader request wins. Changing that separate policy requires a coordinator decision.
