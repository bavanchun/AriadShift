# Phase 9: Cloud backend

## Goal

`ariad-server` runs the `/v1` API and the conversion workers described in ARCHITECTURE §8.3 and §9, on PostgreSQL with pgmq and S3-compatible storage, with the same host conversion code as the CLI, sandboxed and quota-bound.

Read first: ARCHITECTURE §2.3, §8.3, §9, §10, §11, §12, §13; `crates/ariad-host` (convert, workspace, sandbox from phase 2, packs from phase 1).

## Requirements

- `crates/ariad-server`, binary `ariad-server` with `api`, `worker --packs <list>` and `migrate` subcommands; configuration from environment variables with a documented reference.
- API: axum, tower-http (request ids, CORS, compression, timeouts, body limits), OpenAPI 3.1 generated by utoipa and committed at `schemas/openapi.v1.json` with a drift test. Endpoints per §9.1, with uploads as one presigned `PUT` (plan decision): `POST /v1/uploads` returns the URL and an id, `POST /v1/uploads/{id}/complete` verifies size and hash; `POST /v1/plan`; `POST /v1/jobs`; `GET /v1/jobs/{id}`; `GET /v1/jobs/{id}/events` (SSE from `LISTEN/NOTIFY`); `GET /v1/jobs/{id}/outputs` (5-minute presigned URLs); `DELETE /v1/jobs/{id}`; `GET /v1/capabilities`; health and readiness endpoints.
- Data: sqlx migrations for `uploads`, `jobs`, `job_steps`, `job_events`, `artifacts`, `usage_events`, `workspaces`, `plan_entitlements` (seeded with `free`); job lifecycle `queued → running → succeeded | failed | canceled → expired`.
- Queue: pgmq, one queue per pack (`jobs_core`, `jobs_docling`, `jobs_office`) behind a `JobQueue` trait; visibility timeouts, bounded retries, archive on completion.
- Storage: `object_store` (S3-compatible for SeaweedFS and R2, local disk for tests); keys `t/{tenant}/{job}/{in|out}/{sha256}`; TTL sweeper deletes inputs and outputs after one hour by default and marks jobs `expired`.
- Auth: JWT verification against a cached JWKS from Better Auth (`/api/auth/jwks`), API keys checked read-only against Better Auth's `apikey` table, anonymous access for small files with per-IP rate limits and optional Cloudflare Turnstile verification. Every account gets a workspace.
- Limits and quotas from `plan_entitlements`, filling `ariad_core::Limits` (cloud column of §11.2); usage recorded in the append-only `usage_events` ledger with an idempotency key.
- Worker: reads its packs' queues, downloads input to a workspace on tmpfs where available, runs the host conversion with cloud limits and the sandbox in `required` mode on Linux, uploads outputs, emits events and usage, cleans up on every path.
- Observability: `tracing` with optional OTLP export; the metric names in §13; no document content and only hashed file names in logs.
- Dockerfiles under `infra/docker/` on Ubuntu 26.04: `server` (api and core worker, with Pandoc and LibreOffice-free), `worker-docling` (docling pack preinstalled), `worker-office` (LibreOffice 26.8).
- Tests: integration tests against PostgreSQL 18 with pgmq (service container in CI, a `just` recipe locally with Docker) and the local object store, covering the full job path for an MD → DOCX job, quotas, rate limits, TTL, delete, auth failures.

## Acceptance criteria

- `cargo nextest run -p ariad-server` passes with the database available, and skips cleanly without it.
- The OpenAPI document is committed and stable under the drift test.
- ARCHITECTURE §9, §10, §13, the Decision Log, and `docs/api.md` are updated.
