# Phase 14: Web foundation

> Deep-mode note: the Mac PM runs a scout-and-detail pass on `apps/web` immediately before dispatch and updates file paths below; the structure and acceptance here are binding.

## Goal

Rebuild the `apps/web` app shell around tools (not only conversions): a tool hub, a document workspace with a fast PDF viewer, a browser tool runner on `ariad-wasm` + PDFium WASM, a native-only hand-off, and full i18n for 40+ locales from day one — to a visual standard above Stirling-PDF and BentoPDF.

## Product requirements

1. **Tool hub** (`/app`): searchable grid of every tool from `listTools()` grouped like `docs/parity-matrix.md`; ⌘K / Ctrl+K command palette; favourites and recents (local storage); each tool card shows runtime badge (Browser / Desktop / Cloud) and tier badge (Free / Pro).
2. **Workspace**: drop files (multi-file), file tray with thumbnails, page grid with drag-reorder/rotate/delete (drives `pdf.reorder`/`pdf.rotate`/`pdf.delete_pages`), viewer pane, tool inspector panel that renders params from the tool's JSON Schema (generic form renderer: number, enum, boolean, PageRange input with live validation, paper picker, colour, file inputs). Undo/redo stack for page-grid edits before applying.
3. **Runner**: browser tools run in the existing module worker (`apps/web/src/converter/worker.ts`) through `runTool` with the input budget passed from TS (`budgetBytes`); PDFium-backed tools run through EmbedPDF's engine worker; tools whose runtimes exclude `wasm` show an honest **"Run on your computer"** panel with the exact `ashift tool …` command, a copy button and the install link — the `ariadshift://` deep link stays route-only and is extended to the macOS app only in phase 17; "Run in Cloud" appears only for tools whose spec includes `Cloud` (after the phase-13 server task) and a configured cloud env. Never a dead button.
4. **Viewer**: 1,000-page document scrolls at 60 fps on an M-series Mac in Chrome and Safari; thumbnails virtualised; text selection and search; zoom/fit; dark mode.
5. **i18n**: all UI strings through `next-intl`; English source catalogue at the path fixed in `docs/i18n.md`; 40+ locales from the phase-1 list; RTL layout for `ar`, `he`, `fa`, `ur`; locale-prefixed static routes (`/[locale]/app`, `/[locale]/convert/[pair]`) with `generateStaticParams`; language switcher; `hreflang` + sitemap per locale; pseudo-locale `en-XA` for tests; Weblate project on **hosted.weblate.org (free libre/OSS plan)** connected to the repo through git (owner decision 2026-10-31; the owner creates the project — gate item).
6. **Design**: follow `docs/brand/design-direction.md` and `packages/ui` tokens; extend `packages/ui` with: `dialog`, `popover`, `tooltip`, `tabs`, `toggle-group`, `slider`, `command`, `toast`, `progress`, `skeleton`, `page-thumbnail`, `drop-overlay`, `kbd`. Every component has light/dark, focus-visible, reduced-motion behaviour.
7. **Hosting headers and redirects**: static export ignores `next.config` headers/redirects. Headers are generated by `apps/web/scripts/write-static-headers.mjs` from `apps/web/route-headers.mjs` (today only `/app`, `/app/:path*` at lines 11-14) — extend the source patterns to `/:locale/app` and `/:locale/app/:path*`. Old unprefixed URLs move with a generated host redirect file (`_redirects` for Netlify; equivalents documented per host). Chromium/Firefox e2e assert `self.crossOriginIsolated === true` on `/en/app`; **Safari does not support `COEP: credentialless`**, so the Safari acceptance is "all browser tools work without isolation" (no SharedArrayBuffer dependence) — verified by the T0 POC.

## Design reference (owner-approved direction, 2026-11-01)

Approved design: Figma file "AriadShift Web — UI/UX v2" (https://www.figma.com/design/IZG7gPWIECWf6dQmcrn82W): page *Design system* holds the tokens (Color and Color Dark collections, Spacing, Radius), 17 text styles, Lucide 1.61 icons and the shadcn/ui-aligned components; page *Screens* holds one section per screen (01 Home, 02 File insights, 03 Organise pages, 04 Tool result, 05 Command palette, 06 Run on your computer, 07 Compress studio, 08 Recipes & batch, 09 Editor Document + AI, 10 Editor Page mode, 11 Home dark, 12 Drag and drop, 13 Processing, 14 Locked PDF, 15 Recipes empty, 16 Settings; phase-15 tool panels 17 Imposition booklet, 18 Crop, 19 Security, 20 Watermark add, 21 Watermark remove, 22 OCR studio, 23 Annotate, 24 Fill form, 25 Redact mark, 26 Redaction verified, 27 Sign, 28 Signature validation, 29 Compare, 30 Convert), each in English and in Vietnamese (`· VI` sections); the Design system page also documents Foundations, interaction states (hover, pressed, focus, disabled, loading, error), toast, tooltip and the `DocPage` thumbnails. Implement them faithfully with `packages/ui` tokens and `lucide-react`; map the Figma variable names to CSS custom properties as their code syntax says (`var(--color-bg-canvas)` and so on). The earlier claude.ai canvas is superseded. Binding UX principles:

- Intent first: after a drop, read the file locally and offer the next steps (file insights screen), never an empty form.
- Honest runtime: every tool shows Browser, Desktop or Cloud, and a persistent "on this device · 0 bytes uploaded" indicator.
- No dead ends: every result card offers download, open in editor, continue with another tool, save as recipe, and undo.
- Live before/after previews with the outcome stated in numbers (size, pages, fidelity).
- The golden thread (brand motif) marks multi-step progress: recipes, batches, pipelines.
- Keyboard-first: ⌘K palette that understands plain sentences and turns them into a recipe.

File insights (canvas "Signature UX" board) need a local analysis call: `pdf.info` extended with scanned-page count, image DPI, empty required form fields, signature fields, blank pages and metadata/edit-history flags. Add it to the T5 runner scope; analysis runs in the browser worker and never uploads.
