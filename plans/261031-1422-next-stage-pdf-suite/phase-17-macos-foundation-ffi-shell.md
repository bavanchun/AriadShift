# Phase 17: macOS foundation

> Deep-mode note: the Mac PM verifies Xcode/Swift/UniFFI/Sparkle versions and the signing secrets state immediately before dispatch.

## Goal

A truly native macOS app skeleton that opens PDFs instantly, scrolls like Preview, and calls every engine tool through a safe Rust bridge — built, signed, notarized and self-updating from CI.

## Architecture rules

- Swift contains no document logic (AGENTS.md); it calls `ariad-ffi` only. Watch folders and recipe execution run in Rust (phase 13 watcher) exposed through `ariad-ffi`; Swift only shows status.
- `ariad-ffi` is the one crate allowed `unsafe_code` (UniFFI scaffolding): per-crate `[lints]` override with a comment, everything else keeps `deny`/`forbid`.
- `ariad-ffi` exposes coarse-grained async functions: `list_tools()`, `run_tool(request) async throws -> ToolOutcome`, `convert(request) async throws`, `inspect(path)`, `plan(...)`, `ir_load/ir_save` (phase 18), `cancel(token)`, progress via a callback interface. Every exported fn wraps `std::panic::catch_unwind` and maps panics to a typed error (non-throwing UniFFI calls must not exist).
- Swift wraps async results in an actor (`EngineClient`) to satisfy `Sendable`.
- File access: app sandbox **off** for Developer ID build (engines need exec); use security-scoped bookmarks anyway for recent documents to stay App-Store-portable later.

## Performance budgets (XCTest `measure` baselines)

- Cold launch to window ≤ 400 ms on M-series; open 1,000-page PDF to first page ≤ 300 ms; scroll at display refresh rate (no hitch > 16 ms in Instruments sample of 10 s).
- Idle memory ≤ 150 MB with one 100-page document; helper processes exit when idle.
