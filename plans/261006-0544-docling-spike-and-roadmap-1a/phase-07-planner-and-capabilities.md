# Phase 7: Planner and capabilities.json

## Goal

Replace the fixed route table with the planner described in ARCHITECTURE §6.3. It is a weighted graph over formats whose edges are engine capabilities. Edge metrics come from a committed `capabilities.json`, the cost depends on the profile (`editable`, `faithful`, `fast`, `private`), and each decision is explainable with its alternatives. This phase also adds the two hidden hooks the bench harness needs to measure single edges.

- ARCHITECTURE §6.3 (graph, profiles, Dijkstra, explanation format), §14 (bench → `capabilities.json`, committed)
- Phase 6 route table and executor in `crates/ariad-host/src/convert.rs`

## Requirements

Data contract:
- `schemas/capabilities.v0.json`, generated by schemars from `ariad_core::planner::Capabilities` and drift-checked like the other schemas. Its `$id` is under `https://ariadshift.ariadnev.com/schemas/`.
- `crates/ariad-core/data/capabilities.json`, sorted and pretty-printed:
  - `version: "ariad-capabilities/0"`, plus `generated_at` and `bench` metadata (fixture count, Pandoc version, ashift version);
  - `edges[]`, each with:
    - `from`, `to`: typed `Format` values, which serialize as their registry ids (`ariad-ir+json`, `docx`, …) through phase 3's wire-id rule, so the schema validates them and they match the protocol strings;
    - `engine` (`ariad-core` or `pandoc`);
    - `runtime` (`["wasm", "local"]` for core, `["local"]` for Pandoc);
    - `license`;
    - `metrics`, which is either `null` or `{fidelity, editability, p50_ms, peak_mem_mb, samples}`.
- This phase commits a bootstrap file in which every edge has `metrics: null`. Phase 8 fills it with measured numbers.

Planner (`ariad_core::planner`, I/O-free, WASM-safe):
- `plan(caps, from, to, profile, available_engines) -> Result<Plan, PlanError>`, using Dijkstra over edges that are available and allowed by the profile (`private` keeps only edges whose runtime includes `local` or `wasm`). The full machinery (profiles, weights, alternatives) ships in 1a by user decision, although each 1a format has one reader and one writer. Its tests therefore use synthetic capability sets with competing edges (two readers for one format, unmeasured versus measured, a cloud-only edge), so profiles and alternatives are exercised before 1b adds real competitors.
- **Cost per edge**, by profile:
  - `w_f × (1 − fidelity) + w_e × (1 − editability) + w_t × normalized(p50_ms) + hop_penalty`;
  - weights for `editable`, `faithful` and `fast` are constants in one table, with doc comments;
  - an unmeasured edge uses a pessimistic default cost and is flagged as unmeasured in the explanation.
- Ties break deterministically on the engine id, then on the format id.
- `Plan` holds the route steps, the aggregated score (fidelity and editability multiply along the route, time adds), a `measured` flag, and up to 2 alternatives. The alternatives are the best route found when each edge of the best route is removed in turn, deduplicated.
- `PlanError::NoRoute` lists the reachable targets from `from`.

Host and CLI:
- **Single availability source.** `ariad-host::engines::availability()` asks each out-of-process engine for `describe` (phase 3) and treats status `found` as available; `ariad-core` is always available. `convert`, `plan`, `engines` and `doctor` all use this one function. The host asks the planner, then runs the chosen route through the phase 6 executor. The fixed table is deleted.
- `ashift convert --profile <p>`, defaulting to `editable`. Exit 3 now prints the reachable targets from the planner.
- The file lives inside the `ariad-core` package (`crates/ariad-core/data/capabilities.json`), because the crates are published to crates.io and `cargo package` rejects `include_str!` paths outside the package. `ariad_core::planner::embedded()` includes it at compile time, which also serves the future `ariad-wasm`. A parse failure is a bug: a test proves the embedded file parses. `bench/` writes to this path.
- Hidden hooks for phase 8. Both are excluded from `--help` and stable only for the bench:
  - `ashift __ir <INPUT> -o <ir.json>` runs one reader edge;
  - `ashift __write <ir.json> --to <fmt> -o <out>` runs one writer edge.
- One coverage test, in Rust, checks that every edge the executor can run appears in `capabilities.json`, and vice versa. It is the only coverage check: the bench does not re-check it and `doctor` does not either, because the file is compiled into the binary.

## Success criteria

- Every phase 6 route still produces byte-identical goldens through the planner.
- With the bootstrap file, `editable` chooses the same routes the fixed table did. A unit test asserts this, so the switch changes no behaviour.
- The embedded capabilities, the schema and the executor's edges are consistent, and a test fails if any drifts.

## Risk assessment

| Risk | Signal | Response |
|---|---|---|
| Multi-hop routes appear where a direct edge exists | Plan output shows `md→IR→html→IR→docx` | Every edge passes through IR, so routes are always reader + writer; hop penalty keeps it that way; assert route length 2 in tests |
| `describe` per conversion adds latency | `convert` slower by a process spawn | Measure it; if over 100 ms, cache availability per process run; never fall back to a second availability source |
| Weights are arbitrary | Review questions them | Weights are documented constants; phase 8 data can adjust them in a later change with evidence |
