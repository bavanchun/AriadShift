# Roadmap Phase 0 · Foundations

## Overview

This plan delivers roadmap Phase 0 from [ARCHITECTURE.md §17](../../ARCHITECTURE.md). The phase ends with one real conversion, not an empty scaffold. The flow is:

1. A user runs `ashift convert notes.md --to docx`.
2. `ariad-core` parses the Markdown into IR v0 (`ariad-ir/0`).
3. `ariad-host` resolves images safely, then re-executes the binary as `ashift __engine pandoc`. That engine speaks `ariad-engine/1` and drives a sandboxed Pandoc 3.12.
4. The host stamps real timestamps into the DOCX and promotes it atomically.

CI runs the same `just ci` on Linux, macOS and Windows.

Mode: `--deep`, HOLD SCOPE. Research reports:
- [Toolchain and technical choices](./research/researcher-01-toolchain-report.md)
- [Vietnamese OCR and fixture sources](./research/researcher-02-ocr-fixtures-report.md)

| DOCX timestamps | The host rewrites `core.xml` created/modified to the conversion time (`SOURCE_DATE_EPOCH` for goldens) |
| Markdown extras | Emoji shortcodes on; YAML front matter fills the document metadata |

## Key risks

| Risk | Mitigation |
|---|---|
| Cross-OS behaviour is unverified until CI runs | CI exists from phase 2. Every later phase is verified on three OSes |
| Process-tree kill and cleanup differ per OS | Explicit kill on every non-success path, cancellation, workspace retry, and grandchild tests on all OSes |
| Hostile input (paths, OOXML, YAML, deep nesting) | Lexical path checks before any filesystem call; closed `Raw` formats; link-scheme allow-list; YAML caps with no aliases; finite nesting |
| Flaky or wrong goldens | XML-part snapshots per fixture, raw-XML assertions, pinned Pandoc version, human review |
| Unlimited local defaults (user decision) | Cancellation is mandatory and tested; nesting, blocks and front matter stay finite |
