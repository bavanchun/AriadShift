## 3. Contract and architecture notes

- Finding 1 contradicts the documented cap. ARCHITECTURE §8.1 says "The browser converter accepts inputs up to 16 MB", and `docs/web.md` step 2 says "Inputs over 16 MB are refused". Six routes refuse some inputs that are under 16 MB.
- Finding 2 is not an ARCHITECTURE violation. The §11.2 cancellability sentence covers native runs only.
- Finding 3 does not break the AGENTS.md Licensing rules: the Pandoc WASM notices and source links are present, and no forbidden licence is shipped. It is a licence-obligation gap (MIT, BSD, Apache-2.0 §4, MPL-2.0 §3.2) for the website distribution.

## 4. Test gaps that matter

- Finding 1: no test runs a two-group route with an intermediate IR larger than the input cap. A fake-core unit test of `ConverterSession.convert` and `runRoute` is enough to pin the limits passed to each engine call. An e2e test with an image-heavy DOCX close to the cap would cover the real path.
- Finding 2: no test cancels or replaces the worker during a running `convert` and checks that pending promises settle and the old session is retired.
- Finding 3: no test checks that the `/licenses` links resolve to served files in the `next start` and export builds, or that the web notices stay current.

## 5. Unresolved questions

1. Is `github.com/bavanchun/AriadShift` public? The `gh repo view` check was not approved in this session, so it remains unverified. The `NOTICE` link on `/licenses` depends on it.
2. Does the Next.js production minifier keep `@license` banner comments in the JS chunks? This is unverified. Even if it does, banners such as React's point to a LICENSE file instead of carrying the full text, so finding 3 still stands.
3. How large must a text-only PDF be to push the pretty-printed IR past 16 MiB? This variant of finding 1 was not measured.
4. Which cancellation behaviour does the product want: terminate the worker and keep the input metadata for a retry, or terminate and start over?
