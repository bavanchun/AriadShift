# PR #84 review: infra, CI, scripts, docs and E2E tests

Scope: `origin/feat/cloud-product` (`796c83e`) against `origin/dev` (`e6bd29b`, merge base `8782c49`). Files reviewed: `.github/workflows/cloud-e2e.yml`, `infra/**`, `scripts/ci-scope.sh`, `scripts/test-ci-scope.sh`, `justfile`, `docs/{api,ci,self-hosting,web}.md`, `ARCHITECTURE.md`, `apps/web/e2e/{cloud,account}.spec.ts`, plus the server, host and auth code these files depend on. Read-only review; nothing was built or run. GitHub could not be queried from this session.

## 1. Verdict

Needs fixes. Even when the compose E2E runs, it does not prove that a scanned PDF goes through Docling OCR. Its CI job also cannot pass until a signed Docling pack and a 0.2.x host exist, so the v1 acceptance item "scanned PDF → DOCX in the sandboxed worker" is still unproven.

Checked and found correct:

- **Quota.** The quota arithmetic is right. The seeded `free` plan has `concurrent_jobs = 4` and `jobs_per_day = 200`, so four pending uploads are admitted and the fifth gets `429 quota_exceeded` from `admit_upload` (`crates/ariad-server/src/entitlements.rs:128-153`). The earlier completed upload and the deleted job do not count.
- **Deletion.** The deletion checks match the server: 204 on delete, then `expired`, then 410 for outputs (`api/jobs.rs:278-286`, `:379`). API-key lookups are not cached (`auth/api_key.rs`), so the 401 after account deletion is deterministic.
- **No external accounts.** Email verification is off (`services/auth/src/auth.ts:61`). The Turnstile secret is blanked, OAuth is empty and anonymous access is on.
- **Production signing path unchanged.** The local-pack override leaves the production image and its signed-pack requirement untouched. The override image has its own tag and an empty build context.
- **Workflow hygiene.** Permissions are minimal, event values reach the script only through environment variables, and the `static` job lints the workflow with actionlint and zizmor (`justfile:27-29`, `ci.yml:113`).
- **`docs/api.md` spot checks.** The numbers I checked match the code: the 1 MiB body limit, `deny_unknown_fields`, the JWKS 300 s TTL with 30 s refresh spacing, the 30 s request timeout and the event payload shape.

## 3. Contract or architecture violations

- **AGENTS.md, "Root tasks go into `just` recipes".** `run.sh` has no recipe, while comparable scripts do (`test-server-container`). Add `cloud-e2e: bash infra/test/e2e/run.sh` and call it from the workflow.
- **ARCHITECTURE.md, OpenAPI as the generated contract.** `docs/api.md` documents three endpoints that are neither in the server nor in the generated document (finding 6). This contradicts both the architecture's "generated from the server code" contract and the page's own rule that the document wins.
- **No other violations.** The test-only override keeps engines out of process and keeps the signed production path. No crate, service or dependency was added that would need a Decision Log entry.

## 4. Test gaps that matter

- **OCR and the actual route.** No test proves that OCR or Docling ran, or which worker and route actually executed the job (finding 1). Sandbox coverage is indirect: `ARIAD_SANDBOX=required` makes worker preflight refuse to start without isolation (`crates/ariad-server/src/sandbox.rs:145-160`), so a healthy worker implies a sandbox. Asserting the executed route, or the worker log line for the job, would make that explicit.
- **Office profile.** The `office` profile starts, but no LibreOffice route is converted. The LibreOffice in the Docling image is never exercised either.
- **Quotas and rate limits.** Only upload admission is tested. The job-creation quota (`Entitlement::admit`) and rate limits are not. The roadmap acceptance (`plans/261022-2128-roadmap-1b-to-v1-product/plan.md:102`) says "quotas and rate limits are enforced".
- **Web and SDK against compose.** The web image is built but never requested. Neither web cloud mode nor the SDK runs against compose, although phase 5's acceptance asks for both (`phase-05-cloud-product.md:35`).
- **Playwright cloud and account specs.** These are fully mocked and gated on `NEXT_PUBLIC_ARIAD_API_URL` (`apps/web/e2e/cloud.spec.ts:17`, `account.spec.ts:255`). No workflow or `just` recipe sets that variable, so the configured-cloud cases never run in CI.
- **Shell linting.** `run.sh` gets no shell lint in CI. The repository has no shellcheck, and `bash -n` ran only by hand.
- **No recorded pass.** No passing run of `run.sh` is recorded in either mode.
