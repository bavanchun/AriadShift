## 3. Contract and architecture violations

- **AGENTS.md licensing rule.** M1 lets AGPL code pass the pack gate, which is a direct risk to "distributed artifacts must not contain AGPL". M2 does not breach AGENTS.md as written: GPL-with-GCC-exception and LGPL are OSI-approved and not AGPL. It does contradict ARCHITECTURE `:516` and `licenses.py:3`, which claim a "no GPL" gate, and the gate's own refusal of LGPL.
- **ARCHITECTURE §11.3** ("launcher enforcement errors fail with `sandbox_unavailable` in both modes"). The session path still breaks this in code (M5), but only for failures that the pool's describe pre-check does not catch.
- **ARCHITECTURE §7/§11.1** ("Writer/Calc link updates disabled"). The verification here does not contradict it (M3).
- **Undocumented limit.** The 64 MiB per-entry DOCX/EPUB cap (M6) is not documented anywhere and does not match the local "workload-sized limits unlimited" stance (`limits.rs:53`).

## 4. Test gaps that matter

- `test_licenses.py`: add a free-text `License` field that conflicts with a known classifier, and a GPL/AGPL classifier next to an MIT classifier (M1). No test runs a native-file inventory over `site-packages` (M2).
- No DOCX/EPUB stamping test with a media entry over 64 MiB, and no Markdown→DOCX test with a large data-URI image under local limits (M6).
- No runner test for a successful one-shot engine whose descendant holds stderr or outlives it. `tests/runner.rs` covers only timeout and cancel (M4).
- No session-mode launcher-failure test (M5).
- No behavioural LibreOffice link-update test (M3).

## 5. Unresolved questions

1. Is GPL-3.0-with-GCC-exception (`libgomp`) or LGPL (`libquadmath`) acceptable inside the Docling pack? AGENTS.md allows them; the gate and ARCHITECTURE `:516` say no GPL. The answer sets M2's severity and the fix.
2. Does a built Linux x86_64 pack actually contain `torch.libs/libgomp*`? Do the locked numpy/scipy wheels' `LICENSE.txt` files cover their vendored libraries? Answering this needs one built pack or the wheels.
3. M3: confirm against `officecfg/.../Writer.xcs` at `libreoffice-24.2.0.3`, and check whether a document-level `LinkUpdateMode=AUTO` in `settings.xml` overrides the profile under headless `--convert-to`.
4. M6: should the 64 MiB per-entry cap stay for the web (`stamp_bytes`), where browser memory may justify it, while native paths drop it?
