# Review: `origin/feat/v1-distribution` against `origin/dev`

Date: 2026-10-27 (Asia/Saigon). Reviewer: Mac console, read-only.

Scope: `git diff origin/dev...origin/feat/v1-distribution` (head `2e860da`, merge base `e0f68a8`, 34 commits, 46 files), plus the surrounding code that the diff touches (`ariad-host` pack signature checks, the pack index, the Docling pack builder, `justfile`, the cargo-dist config and the full `release.yml` and `desktop.yml`). I also compared the branch with every `origin/feat/v1-distribution--*` ref. Remote refs are as of the last local fetch, because `git fetch` and `gh` queries needed approval in this session. No builds, tests or workflow runs were executed.

## 1. Verdict

**Needs fixes.** The branch is not ready to merge into `dev` as it stands. It is 3 commits behind `dev`, with a guaranteed Cargo version break on integration. The 1.0.0 bump also makes the CI license check fail, and a `v1.0.0` tag cut from it would ship a Docling pack install that refuses every published pack. The desktop checksum and Minisign signing pipeline itself is sound and fails closed.

Checked and found sound:

- `desktop-release-sign.sh` refuses an empty key and a non-stable tag. It rejects malformed checksum lines, verifies against the committed keys and fails if none matches, then re-checks every file with `sha256sum --check --strict`.
- The trusted comment carries no `pack:` token, and `ariad-host/src/packs/signature.rs:138-160` requires one, so a desktop signature cannot pass as a pack signature.
- `sign-release` holds the key with a read-only token and installs no npm dependencies. A separate job with no secrets holds the write permission.
- Partial Apple or Windows secret groups fail the release, and present certificates are verified after the build.
- `verify-homebrew.py` and its tests bind the formula's URLs and hashes to the built bytes for all four Unix targets.
- The public key quoted in `docs/install.md`, `docs/desktop.md` and `docs/release-notes.md` matches `crates/ariad-host/data/pack-keys/d87b0e33f55ea02b.pub`. The updater key ID `CDEBF0BE86A5D2A5` matches `tauri.conf.json`.
- The guard script keeps the tap token confined to the `Push formula` step and allows only the exact boolean availability expression.

## 3. Contract or architecture violations

- **Docs truth.** `AGENTS.md` "Current state" and the README/ARCHITECTURE surface tables claim features that are not on this branch or on `dev` (finding 4). AGENTS.md treats these files as authority, so they must match the merged code.
- **Release scope.** No boundary violation. Conversion logic is untouched (only hint strings changed), engines stay out of process, and the ARCHITECTURE decision log was updated for the desktop trust model. `tauri-action` is pinned by SHA to the stable `v1.0.0` tag; the worker verified the tag-to-commit mapping, and I could not re-check it offline.
- **Commit hygiene (minor).** `2e860da docs(plans): add p8-prep worker report` puts a phase label in a commit message. The user's review rules forbid plan IDs and phase numbers in commit messages.

## 4. Test gaps that matter

- The production signing path is never rehearsed: an encrypted key with `PACK_MINISIGN_KEY_PASSWORD` fed through stdin (`desktop-release-sign.sh:51-52`). The PR rehearsal uses an unencrypted `-W` key, so the first real exercise is the `v1.0.0` tag.
- `collectRelease` has no test: the API download, the GitHub digest check and `requireAllKinds` against real tauri-action 1.0.0 asset names. A stubbed-`gh` unit test would cover it before release day.
- `scripts/test-check-release-workflow.sh` has no mutation cases for the new guard rules: the tap availability flag, the conditional tap steps, the Homebrew verification step, the registry-token skip and the `Push formula` notice. The new rules are only exercised in their passing state.
- No test ties the pack builder's `REQUIRES_ASHIFT` or the `packs.toml` version to the workspace version. Such a test would have caught finding 1.
- Several paths run only on tags: `brew style`, the conditional tap publication, `announce`, and the Apple and Windows signature verification steps (no certificates are configured).
- Per the p8-prep report, nobody has compiled the Rust or run its tests for the changed Pandoc hint strings (`doctor_missing_pandoc_exit_code_5`, the `convert_cli` exit-code test, `protocol::tests`), nor run `just ci` or `just desktop-ci`, on the current head.
