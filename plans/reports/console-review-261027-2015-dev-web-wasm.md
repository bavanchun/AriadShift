# Review: origin/dev web converter, ariad-wasm and ariad-typst

Date: 2026-10-27 (Asia/Saigon). Reviewer: console review, read-only.
Scope: `crates/ariad-wasm`, `crates/ariad-typst`, `apps/web` (converter worker, Pandoc WASM integration, OPFS store, engine cache, service worker, desktop hand-offs, licences page) at `origin/dev` `e6bd29b`. The local `dev` checkout (`68ac304`) has no diff from `origin/dev` in these paths, so the line numbers below hold for both.

## 1. Verdict

Needs fixes: nothing is critical, but three medium defects need fixing before v1. Image-heavy or text-heavy documents fail under the advertised 16 MB limit. A running conversion cannot be cancelled. The website does not serve the licence notices for the code it distributes.

### Areas checked without findings

- **XSS:** converted output is never rendered in the page. There is no preview, `innerHTML`, `iframe` or `srcdoc` in `apps/web/src`; the only `dangerouslySetInnerHTML` is the static theme script in `layout.tsx:34`. File names, `meta.title`, warnings and error messages are rendered as React text. The core HTML writer sanitizes raw HTML blocks and strips inline raw HTML (`crates/ariad-core/src/writer/html.rs:277-287`, `:450-457`). One hardening option: the memory-store download blob keeps the output media type (`file-store.ts:68`). An in-app browser that ignores `download` could open converted HTML as a same-origin `blob:` page, so serving downloads as `application/octet-stream` would close that path. OPFS-backed downloads have no type.
- **Desktop hand-off:** `desktopLink` encodes both parameters (`lib/formats.ts:206-210`). The profile comes from `isProfile`, and the target is restricted to inspection results. The desktop parser accepts the short names, rejects unknown or duplicate parameters, and has no path field (`apps/desktop/src-tauri/src/deep_link.rs:25-75`). No file bytes enter the URL.
- **Pandoc integration:** a single reactor instance is reused with a cleared virtual filesystem map, which follows the upstream `pandoc.js` pattern. The virtual filesystem holds only the input, output and media files. Integrity is checked before caching and compiling, and the browser fails closed.
- **OPFS and locks:** each worker holds a Web Lock on its folder before creating it. The sweep and `retire` take the lock before deleting. `clear()` removes the whole session folder. These are correct.

## 3. Contract and architecture notes

- `apps/web/src/converter/browser-engines.ts:55-67` hard-codes output media types: anything that is not EPUB is labelled DOCX. It also chooses the package timestamp in the surface. Stamping itself correctly lives in core (`stampPackage`), but the media-type table duplicates `Format::media_type()`. If a new browser Pandoc edge is added (for example IR to ODT), the output would be mislabelled. This is borderline with the AGENTS.md rule "Surfaces never carry their own conversion code". Return `media_type` and `extension` from a core bridge instead.
- `crates/ariad-wasm/src/api.rs:262` re-plans each `ariad-core` group independently of the route the worker already planned. Today the two planners agree because browser Pandoc edges only touch DOCX and EPUB. That agreement is an undocumented invariant.
- Licensing (AGENTS.md "Licensing"): Pandoc stays a separate unmodified file with its GPL licence, copyright notices and source links, so that part complies. The notice gap for the other bundled code is finding 3.
- `docs/web.md:40` ("Inputs over 16 MB are refused") does not mention that some heavy routes also fail below that size (finding 1). The docs should be updated together with the fix.

## 4. Test gaps that matter

- No heavy-route test near the input limit. Image-heavy DOCX or EPUB, and text-heavy PDF, to Markdown or HTML would have caught finding 1.
- No test for cancelling or replacing a worker during a long conversion, and no client test for requests in flight when the recycle path retires the worker (finding 6).
- `wasm-cache.test.ts` covers Pandoc's fail-closed paths but has no test for a bad cached Typst entry (finding 5).
- No accessibility assertions for the `/app` states (error, hand-off, result) and no focus-management checks (findings 9 and 10). Keyboard tests exist only for the picker and the selects (`e2e/converter.spec.ts:271-290`).
- No test that the `/licenses` links resolve to served files (`/wasm/pandoc/COPYING.md`, `COPYRIGHT`, `SOURCE.txt`) in the `next start` and export builds.
- No test runs several sequential Pandoc conversions in one worker to check reactor state reuse and memory growth against `RECYCLE_MEMORY_BYTES`.

## 5. Unresolved questions

1. Is "complete corresponding source" for `pandoc.wasm` met by links to the pandoc 3.12 tag? The binary statically links Hackage packages, the GHC RTS and wasi-libc, and it is built with a GHC wasm toolchain and its scripts. Legal should decide whether the exact build recipe and dependency sources (for example a `cabal freeze` file and source tarballs) must be mirrored or listed in `SOURCE.txt`.
2. Is `github.com/bavanchun/AriadShift` public? The `/licenses` page's only route to the font, Typst and MPL notices depends on it.
3. How large is the Pandoc instance's memory after a typical DOCX job? Does it alone exceed the 256 MiB recycle threshold and force a recompile on every file?
4. Should there be a shared `Limits::browser()` profile with finite decompressed, asset and IR JSON caps and a soft timeout? It would fix findings 1 and 4 consistently across `ariad-wasm` and `ariad-typst`.
5. Which cancellation behaviour does the product want: terminate the worker and keep the input, or terminate and start over?
