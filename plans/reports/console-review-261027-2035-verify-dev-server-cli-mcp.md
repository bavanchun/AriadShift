## 3. Contract or architecture violations

- **Finding 1** breaks `ARCHITECTURE.md:220` ("returns `structuredContent` matching CLI `--json` value-for-value") for any input over 32 MiB, both in outcome (error versus success) and in the error code and exit code.
- **Findings 2 and 3:** no AGENTS.md or ARCHITECTURE.md rule is broken. `docs/server.md:97` describes the fixed budget accurately, but it does not say that one client can take all of it.
- No boundary violation was found in the code re-read for this check.

## 4. Test gaps that matter

- MCP: no `inspect`, `plan` or `convert` test with a sparse input of 32 MiB + 1 byte. Such a test should assert parity with the CLI tests at `commands_cli.rs:1200` and `1390`.
- MCP: no test where `roots/list` returns an error (or never answers) after `list_changed`.
- Server: no test that a single subject or token cannot hold every transfer slot, for either PUT replays or concurrent GETs of one output URL.

## 5. Unresolved questions

1. Is `file://` storage with anonymous access a supported production setup? The answer decides whether finding 2 stays medium.
2. Does rmcp 3.5.1 put a timeout on server-to-client requests such as `roots/list`? I could not check, because reading the cargo registry required approval in this session.
3. Is replaying a PUT within the URL window meant to stay allowed (`sweeper.rs:135-139` suggests so)? If not, the `pending` check from the earlier report should be added on top of per-subject admission.
