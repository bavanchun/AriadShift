# CI, justfile and scripts audit (origin/dev)

- Scope: `.github/workflows/*`, `.github/dependabot.yml`, `.github/actionlint.yaml`, `justfile`, `scripts/` on `origin/dev` at `e6bd29b` (2026-10-27). Read through `git show`; nothing was built or run.
- Checked against: `AGENTS.md`, `ARCHITECTURE.md`, `docs/ci.md`, `docs/releasing.md`, `deny.toml`, `committed.toml`, `dist-workspace.toml`, and the code the scripts call (`engines/docling/pack/torch_build.py`, `fetch.py`, `bench/tests/test_heavy.py`, `crates/ariad-cli/tests/support/fixtures.rs`).

## 1. Verdict

**Needs fixes.** Nothing here stops day-to-day merging. But the CI scope logic can mark an unverified Rust tree as green and promote it to `main` without building it. On top of that, three release workflows (`release.yml`, `desktop.yml`, `images.yml`) run on any matching tag without checking the tagged commit first. Fix both before the next release.

## 3. Contract and architecture violations

- **Dependency bot:** ARCHITECTURE.md:41, :677 and :801 say Renovate, grouped, with patch releases automerged once CI passes. The repo uses Dependabot (`.github/dependabot.yml`) with no automerge, and the Decision Log has no entry for the switch. AGENTS.md requires ARCHITECTURE.md and its Decision Log to change together with the code. Dependabot also has no `docker` ecosystem for the digest-pinned CI service images (`ci.yml:285,300`, `justfile:182-183`) or the Dockerfiles.
- **Docling targets:** ARCHITECTURE.md:516 says `pack-docling-v*` tags build four targets, including x86_64 Windows. The workflow builds three (`pack-docling.yml:71-80`). ARCHITECTURE.md:950 describes the LLVM OpenMP Windows DLL slot as current, while `toolchain-wheels.yml:4` defers it to v1.x (#83). `docs/ci.md:15` says torch-docling builds "native Linux and Windows x86_64"; the matrix is Linux only.
- **Fuzz target count:** ARCHITECTURE.md:756 says "Seven targets". `ci.yml:425` and `justfile:291` run nine (`pdf_reader` and `typst_writer` were added).
- **CI scope:** ARCHITECTURE.md:800 says CI runs the three-OS matrix "on every push and pull request". In practice scope-skipping (`docs/ci.md`) leaves it out for docs-only, JS-only and promotion changes. Either the architecture text should point to `docs/ci.md`, or finding 1 should be fixed so the shortcut is sound.
- **Python licence gate:** ARCHITECTURE.md:791 lists Python licence checkers under automated CI gating. The Python gate runs only inside pack builds in the path-filtered `pack-docling.yml`, which is not part of `CI passed`.
- **Brand assets:** AGENTS.md treats `brand/svg`, `brand/png`, `brand/icon-composer` and `brand/preview.png` as generated outputs to commit together with their sources. No CI job rebuilds them and checks for drift. If the PNG output is not byte-reproducible, a check on the SVG output alone would still help.
- **Minor doc drift:** `docs/ci.md:55` lists the web-job trigger paths without `crates/ariad-typst/`, which `ci-scope.sh:24` does include.

These parts are in line with the rules: every `uses:` is pinned to a full SHA; every top-level `permissions` block is `contents: read` or `{}`, and write scopes are granted per job; no `pull_request_target`, `workflow_run` or `issue_comment` triggers; every `actions/checkout` sets `persist-credentials: false`; Pandoc, actionlint, committed, wasm-bindgen, dist and cyclonedx downloads are verified by SHA-256; pnpm uses `--frozen-lockfile` and uv `lock --check`/`--frozen`; the fixture manifest (licence allowlist and every file listed) is enforced in `crates/ariad-cli/tests/support/fixtures.rs` and runs whenever `fixtures/` changes (classified heavy); cargo-deny, JS and desktop licence checks run in `just static`; OpenAPI drift is tested in `crates/ariad-server/tests/openapi_drift.rs`; no npm, yarn or pip anywhere.

## 4. Test gaps that matter

- `scripts/test-ci-scope.sh` covers only `--classify`. It never exercises the push range, the `PUSH_BEFORE` fallback or the promotion lookup through `gh api`, which is where finding 1 lives. It also has no cases for `docs/bench-report.md`, `infra/docker/*`, `fixtures/*`, `vendor/*` or `services/auth/Dockerfile` beyond asserting the current (wrong) answer.
- `check-release-workflow.sh` does not inspect the `on:` tag filters, so the overlap in finding 2 goes unnoticed.
- `scripts/check-js-licenses.mjs`'s SPDX evaluator (`satisfies`) has no unit test, unlike `check-crypto-bigint.test.mjs`. A parser bug there would silently allow disallowed licences.
- `scripts/check-commits.sh` has no tests: nothing covers the Dependabot exemption through `committed.toml`'s `ignore_author_re`, the AI-reference pattern, or merge-commit handling.
- No PR job builds the auth or web images (finding 7), and no CI check covers brand-output drift.
