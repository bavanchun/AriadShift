SPDX distinguishes this current BSD licence from the older, separate [Leptonica licence](https://spdx.org/licenses/Leptonica.html). No exception for that older licence is asserted.

Leptonica 1.87.0 was compiled statically with programs and zlib, PNG, JPEG, GIF, TIFF, WebP and OpenJPEG disabled. Tesseract 5.5.4 was built with static libraries and training, tests, OpenMP, TIFF, archive, curl, graphics, native CPU optimization, precompiled headers and ccache disabled. Compilation completed in a temporary directory through the shared lock and a 2 GiB scope; this exploratory build is separate from the reproducibility and pack checks. CMake 4.4.5 was supplied by the manager and selected explicitly in PATH. The unstripped executable's SHA-256 is `15296e214aa3f50b37c345a081cd6eeec362316fcccb58a4a75792e3097cd317`. Its dynamic dependencies are system `libstdc++.so.6`, `libm.so.6`, `libgcc_s.so.1`, `libc.so.6` and the system loader. The highest referenced glibc symbol is `GLIBC_2.43`, so this local development executable is not evidence for the release baseline.

The development executable and hash-verified `vie`, `eng` and `osd` models are at `/home/vchun/Codes/01-AriadShift/.run/coord/tesseract/5.5.4/linux-x64/`; `READY` records the executable hash and version. With the fixture converted to PGM, `bwrap --ro-bind / / --dev /dev --proc /proc --unshare-net` plus Tesseract `-l vie+eng` returned the Vietnamese text successfully. The same network-isolated invocation with `--dpi 300 --psm 0` returned rotation 0, orientation confidence 13.52, script Latin and script confidence 3.91. Both returned zero. Both emitted warnings that an internal Leptonica bitmap font could not be read because TIFF support was disabled; OSD additionally reported a 70 dpi fallback. Those warnings need evaluation with the complete adapter and other inputs.

The source compiler is now in `engines/tesseract/pack/compile-tesseract.sh`, following the existing qpdf pack layout. Shellcheck and the source-hash rejection checks pass. Two separate Linux builds from the pinned archives produced identical stripped executables, SHA-256 `fa1c6da3b59d7942bc283bf2e08c073c35e75b864fb1c8766f9e6035cbd3ca28`. No signed-manifest verification, release dependency audit or CI result is claimed.

This workflow has passed actionlint but has not run on the CI platforms. Its Linux builds use the same pinned manylinux images as qpdf and compare two independently compiled binaries.

The adapter shares the executable path and manifest validation with qpdf. Its focused tests passed against the actual Tesseract binary. OSD initially failed because Tesseract treated a leading-dot temporary filename as a zone-file basename; using a non-dot PGM filename repaired the real fixture. The existing qpdf secret test on `dev` assumed newline secrets could be inserted before validation; it was corrected to assert rejection at `SecretBag::with`, and the real qpdf adapter and secret tests then passed 15 cases.

The first `just pack-tesseract-verify` attempt started compiling into the worktree's default `target/`: the shared lock only sets `CARGO_TARGET_DIR` automatically when its first argument is `cargo`, not when invoking `just` through `env`. The attempt was stopped immediately. The retry explicitly exports the existing shared target directory before taking the lock. The partial worktree target was left intact under the no-clean rule.

The first `just pack-tesseract` attempt used the mise shim for `just`, which put an unconfigured CMake shim ahead of the manager-supplied binary despite the PATH export. It failed before compilation. The retry invokes the installed `just` 1.58.0 binary directly after exporting the required CMake path and shared cargo target.
