# Review: origin/dev — ariad-server, ariad-cli (incl. `ashift mcp`), apps/desktop

- Ref reviewed: `origin/dev` at `e6bd29b` (2026-10-27 13:37 +0700). Not re-fetched. `crates/ariad-cli/src`, `crates/ariad-host/src` and `apps/desktop` are byte-identical between local `dev` and `origin/dev`. Server files that differ were read with `git show origin/dev:<path>`.
- Scope: everything under `crates/ariad-server/src` and its migrations (headers only); `crates/ariad-cli/src` (`main.rs`, `batch.rs`, `render.rs`, `mcp/*`); `apps/desktop/src-tauri` (backend, watch, deep links, capability and permission files, `tauri.conf.json`) and the IPC and deep-link parts of `src/app.tsx`. I also read the `ariad-host` code that MCP depends on: `confine.rs`, `assets.rs`, and the `ConvertError` exit codes in `convert.rs`.
- Method: read-only. Nothing was built or run. Every line number below refers to `origin/dev`.

## 1. Verdict

**Needs fixes.** I found nothing critical. However, the MCP server refuses every input larger than 32 MiB with the wrong error code, which breaks its documented parity with the CLI. A local-store server can also have its transfer budget exhausted by one anonymous client. Fix both before treating these surfaces as v1-ready.

Checked and found sound (no finding):
- JWT verification refuses HMAC algorithms, matches each key's declared algorithm, requires `exp`, `iss`, `aud` and a non-empty `sub`, and caps cache age at 15 min with throttled refetches (`auth/jwt.rs`).
- The API key path is read-only and handles config id, disabled, expired, exhausted and rate-window states (`auth/api_key.rs`).
- The failed-credential throttle runs before verification (`api/mod.rs:114-145`).
- Blob tokens use a constant-time HMAC comparison and bind method, key, expiry, size and hash (`storage.rs:363-375`).
- Upload completion verifies size and hash and deletes mismatches.
- Workers take an advisory lock per job, update status with guards, and delete orphaned outputs (`worker.rs:545-576`).
- The SSE lease caps hold, and the internal error type never leaks causes to clients.
- The Tauri capability is scoped to the `main` window. Commands go through generated `allow-*` permissions, the CSP has no remote sources, deep links carry no paths, and the watch output is re-canonicalized under the chosen folder.

## 3. Contract / architecture violations

- **MCP–CLI parity (`ARCHITECTURE.md:220`, "matching CLI `--json` value-for-value"):** this is broken for inputs over 32 MiB (finding 1) and for error exit codes (finding 4).
- **Relative paths (`ARCHITECTURE.md:221`, `docs/mcp.md:85`):** the docs contradict the code (finding 6).
- **`docs/mcp.md:103`:** describes per-call root queries that the code does not implement (finding 5).
- **Desktop plugin list (`ARCHITECTURE.md:553`):** lists `deep-link`, `updater`, `single-instance` and `dialog`. The app also ships `tauri-plugin-opener` (`apps/desktop/src-tauri/Cargo.toml:32`, `lib.rs:35`, capability `opener:allow-reveal-item-in-dir`). Neither §8.2 nor the Decision Log records it, and AGENTS.md requires ARCHITECTURE.md to be updated in the same change as a new dependency.
- **No boundary violations:** the CLI, MCP, desktop and server all delegate conversion to `ariad-host`, and engines stay out of process.

## 4. Test gaps that matter

- MCP: no test with an input over 32 MiB for `inspect`, `plan` or `convert`.
- MCP: no test where `roots/list` fails after `list_changed`.
- MCP: no test of a stateless (no `initialize`) client using roots.
- MCP: no test asserting that the `exit_code` and `code` in structured errors equal the CLI's for the same failure.
- Server: `tests/blob-transfers.rs` covers replay of the *same key at the same time* and expiry, but not a PUT replay after `complete` or `DELETE`. It also has no test that one subject cannot hold every transfer slot.
- Server: no test for `create_job` or `plan` on an upload that is completed but past its expiry.
- Desktop: no test of startup with a malformed or out-of-range `desktop.json`.
- CLI: no test for `ashift` with no subcommand. The batch case-collision case is untested.

## 5. Unresolved questions

1. Is `file://` storage meant for production self-hosting, or only for development and single-user setups? That decides whether finding 2 is medium or low.
2. Does rmcp 3.5.1 cancel a request's `CancellationToken` when the request completes? If it does, finding 8 does not apply.
3. Can a tool call that arrives right after `notifications/initialized` race the asynchronous roots refresh and see an empty allowed set? Several tests call `wait_for_roots_refresh` first, which hints at this. I have not verified it against real clients.
4. Should MCP `plan` and `convert` expose the CLI's `--engine` reader pin? It is currently missing from the tool schemas. That is a parity gap rather than a defect.
5. Does `tauri-plugin-opener` 2.7.2's `reveal_item_in_dir` enforce a path scope? I could not check this: reading the cargo registry is outside this session's allowed paths.
