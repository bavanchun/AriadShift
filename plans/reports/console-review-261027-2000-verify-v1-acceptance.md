## 3. Contract and architecture violations

- I found no new AGENTS.md or ARCHITECTURE.md boundary violation in the verified scope. The remote MCP audience is kept separate from the REST audience (`hardening:crates/ariad-server/src/mcp/mod.rs:59-66,178-182`).
- There is a records-integrity problem: hardening's `worker-p6-oauth-rev.md` claims a High fix that is not on the branch. A merge reviewer who trusts the plan records would wrongly treat the issue as closed.

## 4. Test gaps that matter

- Hardening has no registration body-cap or rate-limit test, because the fix and its tests (`app.test.ts`, `auth.test.ts` in `e7101d8`) are absent.
- `oauth-lock.ts` has no test showing that a single address flooding the token endpoint is refused before it takes admission or the lock.
- The R2 re-land needs a stalled-tail download test, in addition to the never-run `blob-transfers.rs`, `assets.rs`, `confine.rs` and `headers.test.ts` suites the earlier report listed.
- Cloud E2E has no path that runs on the PR without the published pack, so the cloud-product and hardening PRs cannot get a green Compose check until the release exists.
