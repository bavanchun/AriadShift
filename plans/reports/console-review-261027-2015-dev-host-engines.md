# Review: `crates/ariad-host` and `engines/` on origin/dev

- Reviewed ref: `origin/dev` at `e6bd29b` ("build(docling): exclude proprietary Intel components from packs (#51)").
- Local `dev` is at `68ac304`, two commits behind. `crates/ariad-host` and `engines/docling/src` are byte-identical between the two, so their line numbers below hold for both. Only `engines/docling/pack/*`, `engines/docling/pyproject.toml` and `engines/docling/tests/test_pack.py` differ; those were read with `git show origin/dev:<path>`.
- Scope: the engine registry, the out-of-process runner and session pool, the Linux sandbox launcher, confinement, workspaces, the Pandoc/Typst/LibreOffice/Docling/PDF adapters, pack fetch/verify/extract/install, and the Docling engine and pack build scripts.
- Method: read-only. Five parallel slice reviews, then the controller re-read every medium finding and a sample of the low ones against the source. Nothing was built or run.

## 1. Verdict

**Needs fixes.** There are no critical or high findings, and the core security boundaries hold, but six medium defects should be fixed before `dev` is promoted to `main`:

- Two are licence-gate gaps that put the AGENTS.md licensing rule at risk.
- One is a possibly inverted LibreOffice Writer link-update setting (unverified).
- One is a Unix process-tree cleanup gap on the success path.
- One is a sandbox-launch failure that the session path misreports.
- One makes DOCX/EPUB stamping fail on media entries over 64 MiB.

**Boundaries that hold** (each checked in code):

- **Pack signatures:**
  - minisign verification refuses legacy signatures and fails closed with an empty key set.
  - The trusted comment is matched token by token, so `pack:docling-evil` and `version:1.0.0-x` fail.
  - The bytes that are verified are the bytes that are parsed (`packs/signature.rs:99-160`, `packs/install.rs:316-343`).
- **Hashing:** SHA-256 and size are checked while streaming, a retry truncates the file and starts the hash over, and cached files are re-hashed before reuse (`packs/fetch.rs:266-270`, `packs/install.rs:535-543`).
- **Extraction:**
  - Entry names that are absolute, contain `..`, `\`, `:` or control characters are rejected.
  - Nothing is written through a link, and files are opened with `create_new`.
  - Links pass both a lexical check and a canonicalize check.
  - Exact size and entry-count budgets apply (`packs/extract.rs:171-185`, `:420-571`, `:666-688`).
- **Inputs (copy before inspect):** the source is opened once, copied under a byte cap, and only the copy is preflighted and handed to the engine (`convert.rs:1637-1687`).
- **Engine artifacts:** they are confined to an output-directory handle opened before launch, opened with `O_NOFOLLOW`, and checked by dev/inode (`workspace.rs:124-144`).
- **Runner environment and bounds:**
  - The cleared environment matches the ARCHITECTURE §7 allow-list (`runner.rs:537-571`).
  - Request and event lines are capped at 1 MiB, and the stderr tail at 64 KiB.
  - Protocol violations are rejected: a line after `result`, `capabilities` during convert, and ok/error fields that disagree.
- **Required sandbox mode** fails closed. Seccomp also covers x32, and private `/tmp` mount errors abort the launch.
- **Pandoc arguments:** every invocation passes `--sandbox` with absolute, validated paths, so no argument can start with `-`, `@` or `+RTS`. The cleared environment also drops `GHC_RTS`.
- **Docling protocol and arguments:**
  - The engine duplicates fd 1 before any third-party import (`__main__.py:11-15`), emits exactly one `result` per request, and follows the session rules.
  - Tesseract `-l` values must match an existing `.traineddata` stem.
- **Docling pack build inputs:** locked wheels install with `--require-hashes --only-binary :all:`, every tar extraction uses `filter="data"`, and no subprocess call uses `shell=True`.
- **Error messages:** the host maps them to fixed strings and drops engine `error.message` (`convert.rs:1781-1810`, `engines/docling.rs:169-176`).

## 3. Contract and architecture violations

- **AGENTS.md licensing rule.**
  - M1 and M2 let GPL/AGPL, or unlisted GPL-with-exception or LGPL native objects, into a distributed artifact without the gate catching them.
  - `licenses.py:38` allows `CC0-1.0`, which is not OSI-approved, against the ban on non-OSI code in distributed artifacts. This needs an explicit decision, either as a recorded exception or removed from the allow-list.
- **ARCHITECTURE §11.3** says launcher enforcement errors fail with `sandbox_unavailable` in both modes. The session path violates this (M5).
- **ARCHITECTURE §7 and §11.1** say Writer and Calc link updates are disabled. This may be false for Writer (M3, unverified).
- **ARCHITECTURE §11.2** says IR reading avoids whole-file buffering and double residency. That is true only for engine artifacts, not for user IR input or the Pandoc writer (L16).
- **Docs gaps:**
  - The 64 MiB per-entry stamping cap (M6) is undocumented.
  - `docs/packs.md:121` ("a damaged one is replaced") overstates `verify` (L5).
  - The Windows comment at `runner.rs:734-735` ("no background child survives the engine") has no Unix counterpart (M4).
- **No crate, app or dependency boundary violations.** Engines run out of process, Pandoc is never linked, and conversion logic stays in `ariad-core`/`ariad-host`.

## 4. Test gaps that matter

- **Licence gate:** no test with a conflicting `License` field and classifiers, or with an unknown or GPL licence classifier (M1).
- **Vendored libraries:** no inventory or test for vendored `*.libs`/`torch/lib` shared objects (M2), and no vendor-scan test for extension-less ELF files (L20).
- **LibreOffice:** no behavioural test that link updates are actually disabled; the current test only checks the written string (M3).
- **Runner cleanup:** no test of a successful one-shot engine that leaves a descendant holding stderr, or a detached descendant. `tests/runner.rs:306` and `:331` cover only timeout and cancel (M4).
- **Session launcher:** no launcher-failure test in session mode; `tests/sandbox.rs:64` covers only describe and one-shot (M5).
- **Stamping:** no DOCX/EPUB stamping test with a media entry over 64 MiB (M6).
- **Pack signatures and extraction:**
  - There is no negative test for a legacy minisign signature, or for an edited trusted comment that was not re-signed.
  - Zip archives have only a happy-path test; traversal, symlink, encrypted and special-mode entries are untested.
  - Nothing tests the `RECEIPT.toml` case collision (L3), and there is no negative test for a hard link to a later or missing file.
- **Workspace and confinement:** no test of no-clobber `promote_into` without hard-link support (L7), no assertion on output permissions (L8), and no `confine_output` oracle test (L10).
- **Pandoc limits:** no test of `timeout_s` 1 or 2 (L14), and none of the local warning flood (L13).

## 5. Unresolved questions

1. What does Writer `Content/Update/Link=2` mean in LibreOffice ≥24.2? Does a document-level `LinkUpdateMode` override the profile, and does headless `--convert-to` answer the link prompt with "no"? (M3)
2. Does any shipped engine leave a stderr-holding descendant after `result`? Candidates are LibreOffice's `soffice.bin` and Docling's Tesseract or RapidOCR subprocesses. The answer decides whether M4 is a live bug or a hardening item.
3. Is GPL-3.0-with-GCC-runtime-exception (`libgomp`) or LGPL (`libquadmath`, `libgfortran`) acceptable in the Docling pack, and is `CC0-1.0` intended to be allowed?
4. Should `ASHIFT_PACK_<NAME>` (an unsigned pack directory, honoured on every surface including desktop and MCP, with no `requires_ashift` check at `packs/mod.rs:448-481`) stay enabled in release builds?
5. Is `engines verify` meant to detect tampering or only corruption? The answer decides whether L5 is a code fix or a docs fix.
6. Will `pack-docling-v*` tag builds restore the native and sccache caches, or will the toolchain pins be filled in first? (L19)
7. Does the server's API or job store show the `ConvertError::SandboxUnavailable` detail verbatim? That decides the reach of L1.
8. Does the server name stored inputs with their content's real extension? `convert/isolated.rs:133-142` keys the 64 MiB native-reader cap on the extension while the reader is chosen by content sniffing.
9. Is it intended that any Pandoc `CouldNotFetchResource` fails the whole conversion (`engines/pandoc.rs:791-793`), rather than falling back to alt text for externally linked images?
