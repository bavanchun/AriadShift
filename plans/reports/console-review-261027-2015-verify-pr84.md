Seven medium findings hold as reported or stronger: M2, web 1 to 5 and the CI label skip. Five were overstated and are downgraded to low: M1, web 6, the trigger paths, `.env.example` and the docs endpoint table. M3 could not be verified.

## 3. Contract and architecture issues

- **Decision Log gap (confirmed).** Self-service deletion changes the tenant lifecycle that ARCHITECTURE.md describes ("every account owns a workspace"), but the PR has no Decision Log entry for it (S-M1).
- **Unowned client contract (confirmed, low).** The web assumes response shapes for three endpoints that no server or OpenAPI document in the repository defines (I-M6).
- **AGENTS.md "Root tasks go into `just` recipes" (confirmed).** The workflow calls `bash infra/test/e2e/run.sh` directly (`cloud-e2e.yml:132`) instead of through a `just` recipe.
- The conversion boundary holds: no conversion code in a surface, and engines stay out of process.

## 4. Test gaps that matter

- The E2E proves neither OCR nor the executed route (I-H1). This is the gap behind the v1 acceptance claim.
- There is no recorded passing run of `run.sh` in either mode (I-H2).
- No test covers an anonymous transfer failure followed by Retry, or a cancel followed by a re-pick, against the real server (S-M2).
- `safeNextPath` has no tests for control characters (W-1).
- No test covers the auth service being unreachable or returning 5xx for `/app` (W-3), or the cloud chunk failing to load (W-4).
- No test covers a failed sign-out in `/app` (W-5).
- No test covers `delete-user` without a password (S-M3).

## 5. Unresolved questions

1. Does Better Auth 1.7.12's `delete-user` accept a request without `password` on a session younger than `freshAge`? This decides S-M3 and needs the installed package or upstream source.
2. Does `@base-ui/react` 1.9.0's `Button` render `type="button"` by default? Cancel buttons sit inside `<form>`s without an explicit type, for example `account-actions-section.tsx:108` in the delete-account form. As I recall, Base UI's `useButton` defaults native buttons to `type="button"`, so this is likely benign, but I could not check it. If it is wrong, pressing Cancel after typing the password would delete the account, which would be a critical defect. Adding `type="button"` removes the doubt at no cost.
3. Does `pack-docling-v0.2.0` exist yet? `gh` was refused. The answer does not change I-H2, because the host-version gate fails anyway.
4. Will "Compose stack (core, office, docling)" be a required check? The answer decides how much the label skip (I-M3) matters.
